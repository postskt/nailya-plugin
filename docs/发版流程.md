# 发版流程（给任何 AI 会话 / 未来的人类操作者）

> 本文档是奈亚插件发版的唯一权威流程。任何 AI 会话被要求"更新/发版奈亚插件"时，按此执行。

## 角色与位置

| 位置 | 作用 |
|------|------|
| `F:\gemini工作区\插件\奈亚V<版本>.js` | 开发副本（日常改这个） |
| `F:\gemini工作区\nailya-plugin\Nailya.plugin.js` | 发布副本（**固定文件名**，永远指向最新版） |
| `https://github.com/postskt/nailya-plugin` | GitHub 仓库（公开，RisuAI 自动更新源） |
| `test/`（本仓库内） | 回归测试夹具（Node 沙箱 + CDP 实测工具） |

## 发版步骤（每次改版必做）

1. **改代码**：在开发副本上修改。
2. **升版本号**（用户指定的三段规则）：
   - 小改（修 bug/微调）→ 末位 +1
   - 大改（新功能/机制调整）→ 中位 +1，末位归零
   - 底层重构 → 首位 +1
   并同步替换文件内**所有**硬编码版本字符串（`//@version`、`//@display-name`、日志前缀、按钮名、备份 payload，共 16~19 处），文件重命名为 `奈亚V<新版本>.js`。`//@update-url` 一行保持不变。
3. **回归测试**：修改 `test/build.js` 里的插件路径为新文件名，运行 `node build.js && node combined.cjs`，54 项断言必须全部通过。
4. **发布**：把新文件复制覆盖 `F:\gemini工作区\nailya-plugin\Nailya.plugin.js`，然后在该文件夹执行：
   ```
   git add -A
   git commit -m "v<新版本>: 一句话说明"
   git push
   ```
   git 推送凭据已绑定本机（gh CLI 配置），无需登录。
5. **验证**：`https://raw.githubusercontent.com/postskt/nailya-plugin/main/Nailya.plugin.js` 能拉到新版本号。

## 回归测试使用方法

- `test/pre.js`：Risuai API 与 DOM 的 Node 桩；
- `test/post.js`：54 项断言（选图/怀孕/时间/告白/注入器/display）；
- `test/build.js`：把插件源码与桩拼装成 `combined.cjs`（**测试代码必须注入 try 块内部**——V8 中 `async function` 声明不会提升出 try 块）；
- `test/cdp.mjs`：连接真实 RisuAI（需以 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222` 启动）做实地诊断：`node cdp.mjs targets|contexts|console <秒>|net <秒>|netfull <秒> <输出>|eval '<JS>' [上下文id]`。

## 已知重要事实（避免重复踩坑）

- 奈亚所有功能（顶部时间/视觉标签/好感墙/雷达选图）依赖**当前卡已建档**，未建档时全部静默不启动——这是"看起来坏了"的头号原因；
- RisuAI 的 iframe sandbox 带 `allow-modals`，原生弹窗可用；但插件仍统一用两次点击确认；
- `pluginStorage` 是全插件共享的存档级存储，历史遗留键（naiya_v1 等）无害，勿清理；
- `char_manager`（角色卡管理器）与奈亚功能重叠，建议二选一；
- 用户版本号规则与本文件第 2 步一致，发版说明里附一句话改动摘要。
